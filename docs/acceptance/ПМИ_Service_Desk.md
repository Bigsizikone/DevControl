# Программа и методика испытаний Service Desk

Статус: проект к согласованию  
Версия: 1.0  
Основание: [ЧТЗ Service Desk](./ЧТЗ_Service_Desk.md)

## 1. Цель испытаний

Подтвердить соответствие функциональности, разграничения доступа, документооборота, маршрутизации, разработки, учета активов, камер, ИБ, интеграций, отчетов и наблюдаемости требованиям ЧТЗ.

## 2. Объект и стенд

### 2.1. Минимальный стенд

| Компонент | Требование |
| --- | --- |
| Клиент | актуальный Chrome или Edge, разрешен JavaScript |
| Frontend/API | единый локальный origin `http://localhost:3000` для legacy-контура |
| Gateway | `http://localhost:3000` или адрес стенда с маршрутом `/api/v1` |
| БД | PostgreSQL с примененными миграциями 001, 003, 004, 005, 007, 008, 010, 012, 014, 015, 016, 017 |
| Очередь/кэш | RabbitMQ и Redis для целевого контура; отказ этих компонентов проверяется отдельно |
| Файлы | локальное хранилище или S3/MinIO с настроенным лимитом |
| Мониторинг | `/health/live`, `/health/ready`, `/metrics` |

## 3. Порядок проведения

1. Зафиксировать версию сборки, commit, конфигурацию окружения и состояние БД.
2. Проверить доступность health endpoints.
3. Выполнить проверки в порядке, указанном в матрице.
4. Для каждой проверки записать фактический результат, скриншот или JSON ответа API.
5. Дефекту присвоить приоритет: P1 — блокирует приемку, P2 — существенный, P3 — некритичный.
6. Повторить неуспешные проверки после исправления.

## 5. Негативные проверки

- запрос без роли к защищенному endpoint возвращает 401/403;
- неактивный пользователь не может выполнять операции;
- неизвестная система, вид заявки или документ дают 404/400;
- пустой комментарий и некорректная дата отклоняются;
- дублирование номера ERP обрабатывается по согласованному правилу идемпотентности;
- попытка выдать отсутствующее оборудование не изменяет остатки;
- ошибка RabbitMQ/Redis не приводит к потере основной бизнес-записи;
- превышение размера тела запроса возвращает контролируемую ошибку без падения сервиса.

## 6. Критерии прохождения

ПМИ считается пройденной, если все P1-проверки и обязательные P2-проверки имеют результат «Пройдено», отсутствуют открытые дефекты P1, а повторные проверки исправленных дефектов успешны. Результаты переносятся в протокол ПСИ.
